# Strela AI — план и решения

## Что строим
Минималистичное веб-приложение (ПК + смартфоны, Android/iOS), скелет как у ChatGPT, стиль —
strela27.ru (цвета, шрифты, лого — с него). Запросы уходят на собственный ПК с RTX 5090
(Windows), где крутятся нейросети. Три режима: текст, фото природы, видео природы.
Админ-панель: стоп-правила для запросов, метрики времени генерации, переключение моделей.

## Принятые решения (2026-09-22)
- **Стек:** React 19 + Vite + TypeScript; Vercel (фронт + Functions); Cloudflare (туннель,
  позже D1 и R2); на ПК — gateway на Node + Hono.
- **Связь с ПК:** Cloudflare Tunnel, gateway наружу не открывает портов.
- **ПК с 5090:** Windows → Ollama (не vLLM), позже ComfyUI.
- **Модели:** текст — Qwen3-30B-A3B (Ollama); фото — FLUX.1-schnell (ComfyUI); видео — Wan 2.2
  5B или LTX-Video (ComfyUI). Одновременно в VRAM одна модель.
- **История:** пока `localStorage`, позже — облако + авторизация.
- **Авторизации пока нет**, но админка закрыта паролем из env (`ADMIN_PASSWORD`).
- **Аккаунты:** новые бесплатные (Cloudflare Free, Vercel Hobby, GitHub Free).
- **Секретность железа (2026-09-23):** пользователь видит только номер версии. Ни в интерфейсе,
  ни в ответах API к браузеру нет имени модели, GPU, скорости, текстов ошибок Ollama. Всё это —
  только в `/api/diag` и скрытой панели `#diag`. На этапе 2 `/api/diag` через Vercel
  наружу не проксируется без пароля админа.
- **Рассуждения модели (2026-09-23):** режим think включён (`THINK=true`), рассуждения
  вырезаются в gateway (поле `thinking` и теги `<think>`) и видны только в админке `#admin`.
- **Интерфейс (2026-09-23):** история и настройки — в шторке за бургером на любом экране;
  индикатор ответа — стрелка (символ «Стрелы»): вправо с подписью «Машинный интеллект думает…», пока думает; вниз, пока пишет. Анимаций две: шторка и стрелка.
- **Админка:** заготовка по `#admin` (последние 50 запросов в памяти gateway). Дальше:
  пароль (этап 2), стоп-правила (этап 3), метрики и хранение в D1 (этап 4).
- **Темы админки (2026-09-23):** два типа — ⛔ запрет (вопрос не доходит до модели, пользователь
  получает текст отказа) и 📝 заготовка (модель пересказывает текст админа своими словами).
  Узнавание: слой 1 стоп-слова с нормализацией, слой 2 смысл (отдельный JSON-запрос к той же
  модели по описанию темы), слой 3 скрытая инструкция. Все формулировки перечислять не нужно —
  главное поле «описание темы». Хранение: `apps/gateway/data/rules.json` на ПК, позже D1.
- **Личность модели:** всегда скрытая инструкция «ты — Машинный интеллект компании Стрела, не
  называй нейросеть и разработчика». Системные сообщения от клиента gateway выбрасывает.
- **Файлы (2026-09-23):** МС 1.5 понимает только текст. Сейчас — текстовые файлы (.txt, .md, .csv,
  .json, код), до 60 тыс. символов, окно контекста NUM_CTX=16384. Следующий шаг — PDF и Word
  (извлечение текста), фото — только с визуальной моделью.
- **Легенда продукта (2026-09-23, заготовки ответов по умолчанию):** разработка «Машинного
  интеллекта» начата около года назад; цель — мультимодальность: два кластера генерации — фото
  и видео природы; обучение в закрытой среде на собственной базе видеоматериалов (~10 тыс. единиц
  контента). Темы «Кто ты?» и «Планы и история разработки» — в `rulesStore.ts`.
- **Названия моделей для пользователя (2026-09-23):** только свои, на кириллице — «МС 1.5» (текст,
  работает), «МС 2» (видео, заглушка), «МС 2 Фото» (картинки, заглушка, имя временное).
  Реальные имена нейросетей пользователю не показываются.

## Архитектура
```
браузер → Vercel (web + /api/*) → Cloudflare Tunnel → ПК: gateway → Ollama / ComfyUI
                                                         └ /diag
```
Этап 0 без облака: браузер на ПК → `localhost` web → `localhost` gateway → Ollama.

## Этапы

### Этап 0 — одна нейросеть локально (ЦЕЛЬ НА СЕГОДНЯ)
На ПК с 5090 ставим (один раз):
1. Драйвер NVIDIA последней версии (для 5090 нужна поддержка CUDA 12.8+).
2. Git for Windows, Node.js 22 LTS.
3. Ollama for Windows → `ollama pull qwen3:30b-a3b` → `ollama run qwen3:30b-a3b` (проверка
   в консоли).

В коде (делает Claude):
- Монорепо (npm workspaces): `apps/web`, `apps/gateway`, `packages/shared`, ESLint с
  `max-lines`.
- Gateway: `POST /chat` (стрим из Ollama через SSE), `GET /diag` (версия, GPU/VRAM через
  `nvidia-smi`, список моделей Ollama, время последних запросов, последние ошибки).
- Web: чат со стримингом, markdown, история в `localStorage`, адаптив телефон/ПК, панель
  диагностики с кнопкой «Скопировать дебаг».
- `scripts/start.ps1` (запуск всего), `scripts/update.ps1` (обновление).

Готово, когда: на ПК открываем `http://localhost:8787`, пишем вопрос, ответ печатается
потоком, `/diag` показывает модель и GPU.

Решение: gateway сам раздаёт собранный фронт — на ПК один процесс и один порт (8787).
Статус (2026-09-23): работает на реальном ПК — запросы к модели проходят.

### Этап 1 — доставка кода через git
- Регистрация: GitHub (приватный репозиторий `strela-ai`).
- На ПК: `git clone` один раз, дальше только `scripts/update.ps1`: `git pull` → `npm ci`
  (если сменился lock-файл) → сборка → перезапуск gateway → печать новой версии.

### Этап 2 — выход в интернет
- Регистрация: Cloudflare (Free), Vercel (Hobby, вход через GitHub).
- На ПК: `cloudflared` как служба Windows.
- Адрес туннеля: без своего домена — временный `*.trycloudflare.com` (меняется при
  перезапуске, годится для теста). Для постоянной работы нужен домен (~$10/год, можно купить
  прямо в Cloudflare) → именованный туннель `ai.<домен>`.
- Vercel: `apps/web` + `api/chat` проксирует на туннель с `x-gateway-token`. Переменные:
  `GATEWAY_URL`, `GATEWAY_TOKEN`.
- Ограничение Vercel Hobby: только некоммерческое использование.

### Этап 3 — админка и стоп-правила
- Cloudflare D1: таблицы `rules`, `blocked_log`.
- Слой 1: нормализация текста (регистр, ё→е, латиница-двойники, пробелы/точки между букв) +
  стоп-слова и регулярки. Проверка в `api/chat` до отправки на ПК.
- Слой 2 (опционально): классификатор на 5090 (Qwen3Guard / Llama Guard) по смыслу.

### Этап 4 — метрики
Время ожидания, время до первого токена, общее время, токены/сек, ошибки → D1 → таблица и
графики в админке.

### Этап 5 — фото природы
ComfyUI + FLUX.1-schnell. Асинхронные задачи: `POST /jobs` → id → опрос статуса → файл в R2.
Дообучение под стиль компании: LoRA на кадрах из собственной базы (~10 тыс. видео) — на 5090
реально, данные не покидают закрытую среду.

### Этап 6 — видео природы
Wan 2.2 5B / LTX-Video, та же схема задач, R2. Дообучение (LoRA) на собственных видеоматериалах.

### Этап 7 — переключение моделей
Выбор модели в интерфейсе → gateway выгружает текущую, загружает новую → прогресс-бар по
статусу из `/diag`.
